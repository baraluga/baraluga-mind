## 20:05 user

I'm curious about your claude code mod feature. How is it different from plugins, skills, etc?

## 20:05 assistant

A mod is a plugin whose job is to change Claude Code itself. It has the same `plugin.json` manifest as any plugin, plus a TypeScript hooks module that runs inside the engine. Skills and most plugins add things *for Claude to use*. A mod changes *how Claude Code looks and behaves*.

| | What it is | Who it acts on | Runs as |
|---|---|---|---|
| **Skill** | A markdown file of instructions, loaded into context when it's relevant | Claude's reasoning | Text in the prompt |
| **MCP server** | An external process that offers tools or data | Claude's toolbox | A separate process |
| **Classic hooks** (`settings.json`) | Shell commands run on events like PreToolUse or Stop | The tool lifecycle | A shell script that returns JSON or an exit code |
| **Plugin** | A shareable bundle of skills, commands, agents, hooks and MCP servers | Any of the above | A packaging and distribution unit |
| **Mod** | A plugin carrying a hooks module that runs in the engine | Claude Code's UI and behaviour | A sandboxed TypeScript/JSX module that calls the engine directly |

**What mods can do that the others can't:**
- **Draw UI.** Live panes and panels, a band above the prompt, status-line entries, toasts. The drawing is JSX that adapts to the surface (terminal, desktop, VS Code, mobile).
- **Act as middleware.** Every hook is `($, e, next)`. It can block a tool call, rewrite its input before the rest of the chain sees it, or act on the result after `next(e)`. Prompts and the system prompt work the same way: you can add, replace or drop sections.
- **Keep state.** Values can last for the session or across sessions, and writing one redraws whatever reads it.
- **Register things.** Slash commands, tools the model can call, subagent types, timers, model calls and sounds.
- **Hot reload.** You edit the mod and it reloads when the turn ends, without restarting the session.

**Rules of thumb:**
- To teach Claude a workflow, write a **skill**.
- To give Claude access to an external system, use an **MCP server**.
- To run a quick script when a tool fires, use a **classic hook**.
- To package any of these for others, make a **plugin**.
- To change the interface, or intercept and rewrite what the engine does in code, make a **mod**.

A small mod is three files: `plugin.json`, `hooks.json`, and `register.tsx`. If you have a use in mind, like a pane, a guard on certain tool calls, or a status-line widget, I can build one for you.

This comes from the bundled mod-authoring guide for this Claude Code build. I haven't built or tested a mod in this session.

- **Search scales and understands meaning.** `rg` misses paraphrases. At about 300 sources that's fine; at 3,000 it starts to hurt.
- **Keeping facts current is built in.** What took us a rule plus a disciplined nightly agent, they do on every write.
