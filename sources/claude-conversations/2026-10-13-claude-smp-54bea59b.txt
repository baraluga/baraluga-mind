Yes. The simplest way is a background job that upgrades just Codex once a day.

**Recommended: a daily launchd job.** It runs at login and then every 24 hours:

```bash
cat > ~/Library/LaunchAgents/com.user.codex-upgrade.plist <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.user.codex-upgrade</string>
  <key>ProgramArguments</key><array>
    <string>/bin/sh</string><string>-c</string>
    <string>/opt/homebrew/bin/brew update -q && /opt/homebrew/bin/brew upgrade --cask codex</string>
  </array>
  <key>StartInterval</key><integer>86400</integer>
  <key>RunAtLoad</key><true/>
  <key>StandardErrorPath</key><string>/tmp/codex-upgrade.log</string>
</dict></plist>
EOF
```

```bash
launchctl load ~/Library/LaunchAgents/com.user.codex-upgrade.plist
```

**The other options:**
- **`brew autoupdate`** (from the `homebrew/autoupdate` tap) upgrades every Homebrew package on a schedule, not just Codex. Only choose it if you want everything updated automatically.
- **Codex's own update notice:** Codex says when a newer version exists and you upgrade it yourself. That's what you have now.

One risk: upgrades can change what Codex accepts in its config, like the `"ultra"` problem you just hit. A bad update would then break Codex without you noticing. You can check `/tmp/codex-upgrade.log` if it starts failing.
