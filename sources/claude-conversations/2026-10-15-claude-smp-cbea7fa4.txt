## 12:01 assistant (smp-india)

It depends on when the CSV lands in S3. The minute DAG will publish within 5 minutes of that, and the realtime DAG within 10.

- **`india_khaba_generation_minute`** runs every 5 minutes (IST cron `*/5`), so its first run after the file appears publishes.
- **`india_khaba_generation_realtime`** runs every 10 minutes (`*/10`), same idea.
- **Both reprocess the whole day** on every run. Today's earlier hours get published in that first run, so the missed runs leave no gap.
- **Possible delay:** each DAG allows only one run at a time. If a run is still busy (for example, the realtime validation step retrying for up to about 30 minutes), the next run waits for it.

Two things to know:

- **Skipped runs show as success.** In the Airflow UI, a run where the CSV check skipped looks green even though nothing was published. To find the first real publish, look for the check task with an actual success state, or a log line containing `KHABA_SOURCE_PREFLIGHT=`.
- **The two broken days won't fill themselves.** The realtime DAGs only process today's file. The reconciliation DAGs run at 12:00 IST and only process yesterday's. Even if upstream re-uploads the missing dates, anything older than yesterday needs a manual trigger of the reconciliation DAGs (both the 15-minute and the minute one) with `target_date` set to each missing day.
