No, groups aren't sent by default. He's right that the fix is on the Okta side, but it's a claim on the authorization server, not just an extra scope in the app.

**What I found:**
- Atlas logs in against the custom Okta authorization servers in [_authentication.py](deployment/runtime/dash_okta/_authentication.py): `gem.okta-emea.com/.../aus2jp8vmz3yYrDnc0i7` for PROD and `gem-beta.oktapreview.com/.../aus3v6rg3e9zNHMxe0x6` for beta. It asks only for `scope: "openid email profile"`.
- I pulled the public discovery documents for both servers. Neither lists a `groups` scope or a `groups` claim.
  - One caveat: custom claims can be hidden from that public list. So this strongly suggests groups aren't configured, but it doesn't prove it.
- The app already reads groups. `User.groups` reads `id_token["userinfo"]["groups"]`, but nothing calls it yet. Today it would raise a `KeyError` because the claim isn't there.

**Draft reply:**

> Hi Francois, all good, you? Short answer: no, groups aren't exposed by default. I checked our Okta auth servers (PROD and beta) and neither publishes a `groups` scope or claim today. We only request `openid email profile`.
>
> You're half right on scopes. On a custom Okta authorization server, the Okta admins have to add a **`groups` claim** to the auth server:
> - included in the **ID token**
> - value type "Groups"
> - with a filter, e.g. "starts with ATLAS_", so we don't get every group the user is in
> - set to "always include" (or tied to a `groups` scope)
>
> If they tie it to a scope, we just add `groups` to the requested scopes in the app.
>
> Code-wise it's mostly ready: there's already a `User().groups` helper in our Okta module that reads that claim. Once the claim is live, gating a feature is just checking membership in a callback/layout. One thing to keep in mind is that we'd check it on the server side too, not just hide things in the UI.
>
> These auth servers look shared, so the change probably has to go through the Okta/IAM team. I'd ask them to do it on beta first so we can test it. Happy to help wire it up once they have.

Two things I didn't check: the Okta admin console itself (I can't see it, so "no groups claim" rests on the public discovery documents), and whether those auth servers are shared with other apps (I'm inferring that from the URLs).
