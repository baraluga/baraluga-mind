## 13:59 assistant (smp-india)

Mostly yes, with one correction: CI builds the image on every run, but it only publishes a new one when the collector's code changed.

How it works ([ci.yml:68-205](smp-india/.github/workflows/ci.yml:68)):
- **Every run** (PRs, and pushes to dev, qa or prod) builds `darwin-collector:test` and smoke-tests it. There are no path filters, so this always happens.
- **The tag is set by content.** It's `darwin-collector-<sha>`, where `<sha>` is the last commit that touched `services/darwin-collector/Dockerfile` or `src/`. Those are the only things the Dockerfile copies into the image.
- **Publishing** checks ECR for that tag first. If it's already there, it skips the push, so nothing gets overwritten. If it's missing, it pushes. That only happens when the `DARWIN_COLLECTOR_ECR_PUSH` variable is `true` and the role variable for that environment is set. Otherwise CI uploads the image as an artifact and writes the manual push steps in the run summary.
- **Deploying is separate.** It runs from smp-tool with `scripts/deploy_darwin.sh --tag <tag>`, so a push to smp-india never deploys anything.

For your test, this means:
- The change has to be inside `services/darwin-collector/src/` or its `Dockerfile` to get a new tag. A change to the collector's tests, `pyproject.toml`, the DAGs or docs runs the build but reuses the old tag, so nothing new reaches ECR.
- The push needs to go to `dev` to reach the publish step. A PR only builds and tests.

I only read the workflow. I didn't check whether `DARWIN_COLLECTOR_ECR_PUSH` is actually set to `true` on dev. If it isn't, the run hands you an artifact to push yourself instead of pushing to ECR.
