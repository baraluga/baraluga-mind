### DAG Architecture Walkthrough

- DAG = a decorated Python function with two mandatory arguments: dag_id and schedule.
  - Schedule expressed as a cron string, such as every 12:00 or every 15 minutes.
  - Tags, start date, and other fields are optional but included for repo best practices.
- Standardized task structure within a DAG:
  - start_task and end_task: logging only.
  - prepare_output_directory: sets up dirs in EFS (Elastic File System).
  - process_data: core logic.
  - upload_output_task: pushes parquet files to S3, optional per DAG.
  - Email report section: commented out by default, uncomment if needed.
- Data flow: DAG writes parquet to EFS, then optionally uploads to S3 (CDH), then visible in Grafana via AWS Athena.
  - CDH is backed by S3; Grafana reads parquet via Athena SQL plugin.
  - Data source does not have to be TSDB; can also scrape public sites or Aurora.

### CDH and S3 Configuration

- Uploading to S3 requires the CDH dataset to already exist in the CDH project.
  - Dataset key in S3 must exactly match the CDH dataset name.
  - Upload function lives in smp-common, installed as dependency for SMP India.
- S3 bucket structure: environments are dev, QA (pre-prod), and prod.
  - Each dataset folder contains a stage, such as latest.
  - At least one stage required for CDH to work.
  - Schema parquet file defines structure; may be required depending on setup.
- Once dataset is added to CDH project, it appears in Grafana's table explorer and can be queried into dashboards.
